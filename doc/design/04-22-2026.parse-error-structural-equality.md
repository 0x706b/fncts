# ParseError Structural Equality Plan

## Goal

Add `Equatable` support to `packages/schema/src/ParseError/ParseError.ts` so ParseError instances can be compared structurally through
`Equatable.strictEquals` and `Equatable.deepEquals`.

## Scope

Implement structural equality on each concrete `ParseError` subclass and on each nested AST-specific helper node used by those subclasses.

## Comparison Rules

1. Reject non-ParseError values and ParseErrors with different `_tag` values.
2. Use the provided `EqualsContext.comparator` for all nested values so recursive ParseErrors and nested equatable
   values participate correctly.
4. For `Lazy`, compare by reference.
5. Prefer type-owned `[Symbol.equals]` implementations over free comparison utility functions.

## Implementation Shape

1. Add `Equatable` support to each concrete `ParseError` subclass in `packages/schema/src/ParseError/ParseError.ts`.
2. Add `Equatable` support to each nested helper shape in the ParseError module
3. Keep any ad hoc comparison local and minimal.

## Verification

Add focused schema tests covering:

- equal primitive ParseErrors
- unequal ParseErrors with different content

Then run the schema test suite or a targeted subset if full suite runtime is unnecessary.

## Implementation Plan

Implement `Equatable` support directly in `packages/schema/src/ParseError/ParseError.ts` and keep the comparison logic local to each type.

Use option 1 for nested plain objects and arrays:

- delegate all field comparisons to `EqualsContext.comparator`
- rely on `deepEquals` for structural comparison of plain object and array payloads
- keep `strictEquals` reference-based for non-Equatable plain objects and arrays

Implementation steps:

1. Import `EqualsContext` and make each concrete parse error and nested helper node implement `Equatable`.
2. Add a small local parse-error tag guard, mirroring the `AST.ts` style.
3. Implement `[Symbol.equals]` on each class using `_tag` checks plus `context.comparator(...)` for nested fields.
4. Keep `MissingError` equality tag-only.
5. Add a focused `packages/schema/test/ParseError.test.ts` covering equal and unequal parse errors, including nested cases.
6. Run targeted schema tests and adjust if any comparison behavior differs from expectations.
