# AST Structural Equality Plan

## Goal

Add `Equatable` support to `packages/schema/src/AST.ts` so AST instances can be compared structurally through
`Equatable.strictEquals` and `Equatable.deepEquals`.

## Scope

Implement structural equality on each concrete `AST` subclass and on each nested AST-specific helper node used by those subclasses.

Covered node shapes:

- `Declaration`
- `Literal`
- `UniqueSymbol`
- `Enum`
- `TemplateLiteral`
- `Tuple`
- `TypeLiteral`
- `Union`
- `Lazy`
- `Refinement`
- `Transform`
- `Validation`

Covered nested helper shapes:

- `TemplateLiteralSpan`
- `Element`
- `PropertySignature`
- `IndexSignature`
- `ASTAnnotationMap`

## Additional Scope

Implement `Equatable` on `packages/base/src/data/Branded/definition.ts` `Validation` so `AST.Validation`
can compare its `validation` vector structurally through `context.comparator`.

## Comparison Rules

1. Reject non-AST values and ASTs with different `_tag` values.
2. Compare annotations structurally, not by reference.
3. Use the provided `EqualsContext.comparator` for all nested values so recursive ASTs and nested equatable values participate correctly.
4. For function-bearing nodes, compare functions by the comparator as well, which effectively preserves reference equality for functions.
5. For `Lazy`, compare by reference.
6. Prefer type-owned `[Symbol.equals]` implementations over free comparison utility functions.

## Implementation Shape

1. Add `Equatable` support to each concrete `AST` subclass in `packages/schema/src/AST.ts`.
2. Add `Equatable` support to each nested helper shape in the AST module:
   - `TemplateLiteralSpan`
   - `Element`
   - `PropertySignature`
   - `IndexSignature`
   - `ASTAnnotationMap`
3. Add `Equatable` support to branded `Validation` in `packages/base/src/data/Branded/definition.ts`.
4. Rely on `context.comparator` directly for `Vector` and `Maybe` fields now that those container types propagate the caller's comparator.
5. Keep any remaining ad hoc comparison local and minimal. The main expected case is inline tuple comparison for `Enum.enums`.

## Verification

Add focused schema tests covering:

- equal primitive AST nodes
- unequal nodes with different payloads
- equal annotations from different `ASTAnnotationMap` instances
- equal nested tuple/type literal/union structures
- unequal refinement or transform nodes when function references differ
- equal and unequal `AST.Validation` nodes based on branded validation `name` / `validate`
- `Lazy` equality by reference only

Then run the schema test suite or a targeted subset if full suite runtime is unnecessary.
